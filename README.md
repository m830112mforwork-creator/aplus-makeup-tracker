# 國小英語 補課派工與進度追蹤系統

## 這是什麼

沿用原本 Excel「請假補課追蹤表」的欄位設計，改成三個角色（老師／助教／主任）可以同時在線上填寫、即時看到彼此狀態的網頁工具。單一 HTML 檔案 + Firebase 即時資料庫，部署方式跟妳之前的 Library Time、代課排課系統一樣。

## 第一步：建立新的 Firebase 專案

1. 前往 https://console.firebase.google.com ，用妳的 Google 帳號登入
2. 「新增專案」→ 輸入專案名稱（例如 aplus-makeup-tracker）→ 一路下一步建立完成
3. 左側選單「建構」→「Firestore Database」→「建立資料庫」
   - 位置選 `asia-east1`（台灣近）
   - 先選「以測試模式啟動」，這樣才能立刻用（**重要：測試模式規則預設 30 天後會自動鎖住，且目前任何有連結的人都能讀寫資料，請看下方「安全性提醒」**）
4. 左側「專案設定」（齒輪圖示）→ 往下滑到「你的應用程式」→ 點選 `</>` 網頁圖示 → 幫應用程式取個名字 → 註冊
5. 會出現一段 `firebaseConfig = { apiKey: ..., authDomain: ..., ... }`，把這一整包貼給我，或是妳自己打開 `app.js`，找到最上面的 `FIREBASE_CONFIG`，把裡面的值換成妳複製的內容

## 第二步：部署到 GitHub Pages

跟妳之前的做法一樣：開一個新 repo（例如 `aplus-makeup-tracker`），把 `index.html` 和 `app.js` 兩個檔案上傳上去，設定 GitHub Pages 從該 repo 的根目錄發布即可。

## ⚠️ 安全性提醒（請務必看過）

這個系統目前**沒有登入驗證**——右上角輸入姓名只是「顯示用」，方便系統知道要秀出誰的資料，並不是密碼保護。這代表：

- 只要知道這個網址的人，都能看到所有學生的姓名、請假原因、補課紀錄，也能修改任何資料
- Firestore「測試模式」的規則本身也是完全開放讀寫，30 天後會自動失效讓所有讀寫被拒絕（屆時系統會整個打不開，除非手動更新規則）

因為這裡面有學生的個資（姓名、請假原因等），我會建議至少做到：
1. 網址不要公開分享/搜尋引擎收錄（GitHub Pages 預設是公開網址，但沒有連結的人找不到）
2. 請我幫忙把 Firestore 規則從「測試模式」改成「限制只有知道特定金鑰/通關密語的人能讀寫」，或是之後加上真正的帳號登入（Firebase Authentication，可以設定成只有妳指定的 Google 帳號能用）

**如果妳們對外部人員看到這些資料完全不在意（例如系統只會在內部網路/私人群組分享網址），現況也堪用；但如果想更保險，跟我說一聲，我可以下一步幫妳加上簡單的通關密碼或正式登入。**

## 系統邏輯說明

- **老師**：填寫學生請假與缺課資訊、指派補課內容，並從時段表格挑選補課時段（會顯示每個助教/時段的剩餘名額，額滿的時段無法選取）。送出後可以隨時產生「傳給教學部：申請時段」或「傳給教學部：異動通知」的文字。
- **助教/輔導老師**：只會看到指派給自己（姓名要跟主任在「時段設定」裡填的助教姓名完全一致）的待處理清單，完成補課後填寫成果，並可一鍵產生要傳給家長的訊息文字、標記「已通知家長」。
- **主任**：儀表板顯示總數／待補課／逾期／已完成，逾期（缺課日期超過 3 天還沒實際補課）的列會自動標紅；下方是所有紀錄的總表，以及助教時段與名額的設定區（新增 Kevin、Kelly 的時段就是在這裡做）。
